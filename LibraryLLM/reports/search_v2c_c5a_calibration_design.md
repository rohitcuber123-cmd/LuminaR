C5A repairs benchmark inputs and native evidence only. It does not score the repaired corpus, tune confidence, select a policy or alter production Search.

The design targets twenty independently authored core examples in every cell of the five-scope/six-stratum matrix, allowing a buffer above the required fifteen after sealed isolation and semantic review. Each cell requires at least four meaningful patterns. Separately marked derivatives are not core review evidence. Existing calibration contexts retain their lineage; original manifests and reports remain unchanged.

The author sees only a query specification, scoped canonical vocabulary/capabilities, field semantics and a development structural-topology denylist. The author receives no parser predictions, scores, failure classifications or policy outputs. A separate reviewer sees the authored queries/labels and capability contract, with no parser execution or prior evaluation evidence. Review decisions are per case and record unresolved fields and applicability. No arbitrary confidence target is authored.

All non-SMART literal-mode operation families are already exposed in development. They cannot honestly be counted as new isolated calibration core merely by assigning new IDs; this limitation is explicit. The new population emphasizes meaningful composite SMART structures, with titles and technical entities preserved as ordinary query operands rather than inert topology padding.

A separate non-authoring auditor performs a sealed structural audit. Held-out query text and labels never reach authoring or semantic-review agents. Only aggregate overlap counts and colliding new case IDs/hashes may leave that process. New conflicting cases are removed or replaced; held-out material never moves. A collision is not cured by renaming a family.

The resulting accounting distinguishes stored row versions, canonical logical contexts, parser cases, native sequences and individual API boundaries. Matrix coverage counts reviewed new parser core only. Old/native/derivative contexts do not inflate those core cell counts.

Native repair maps the ten original UI intents to genuinely server-issued corrections and tests actual suggestion issuance and selection. Original C5 harness failures remain historical failures. A pre-execution independent review checks the new native oracles and each proposed classification. Exact API status, issuance, accepted/pending/profile state and privacy are measured separately.

Final acceptance requires all matrix, uniqueness, isolation, native/security and preservation gates. If an application defect, a semantic coverage gap or a forbidden overlap remains, C5A is PARTIAL and calibration remains blocked. Inputs can be frozen as a non-ready candidate without claiming authorization for the next calibration run.
