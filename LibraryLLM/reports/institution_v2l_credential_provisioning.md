# Credential boundary — designed; production ownership NOT_QUALIFIED

The integration is disabled unless LUMINAR_WORKER_TELEMETRY_ENABLED is exactly1 and a separate LUMINAR_WORKER_TELEMETRY_MONGO_URI is explicitly supplied. Generic MONGO_URI, MONGO_DB_NAME credentials, application JWTs, Platform/library authority and LUMINAR_OPERATOR_MONGO_URI are never writer fallbacks. Reading worker database identity only binds the separate writer to the same database; it does not copy the native write connection.

An authorized deployment/database administrator must own any future provisioning action. No named production owner, protected secret store, ACL, rotation procedure execution or deployment principal has been verified in this phase. No production user/role/collection/index is created. Fixture provision functions reject non-fixture databases and exist only in task scripts, not the runtime/CLI.

The reviewed custom role grants find/update only on the fixed institution_worker_telemetry_v2k collection, plus find on institution_intelligence_jobs and institution_intelligence_targets for post-ack sampling/correlation. No insert/delete/index/schema grants. Exact effective privileges and a single database-local authenticated user are checked with connectionStatus; an inherited root/readWrite/additional privilege set fails closed. URI requires explicit loopback SCRAM credentials, one endpoint and database=authSource. Writer primary reads, acknowledged journaled writes, retry settings and pool bounds are set by code rather than weakened by URI options. A deployment reviewer must preallocate the singleton, install/verify the accepted strict16384-byte/eight-entry validator and retain only the built-in unique_id index. Runtime never provisions or upserts a missing record.

For a future separately approved deployment, supply the writer secret through an operator-owned OS/service secret facility inherited only by the intended resident worker service account; do not put it in source, command-line arguments, reports, a patron configuration screen or a broad shared .env. A separate URI alone does not enable the observer. Current project environment/.env contain neither the explicit enabled flag nor the dedicated writer credential. Existing local launchers load generic process environments and provide no verified per-worker secret ownership or supervisor attestation; deployment remains NOT_QUALIFIED.

Rotation design: administrator provisions a replacement equally restricted principal, verifies its actual effective grants, replaces the protected secret and performs an explicitly approved worker restart at an independently reconciled safe job boundary. Revoke the former principal after validating the replacement; do not assume password rotation immediately invalidates every authenticated connection. Revocation is tested in auth-enabled fixtures; native jobs continue while telemetry fails, and the same observer resumes after permissions return. A new instance must fence old telemetry epochs. No rotation/restart automation is implemented.

Failure policy: no URI or invalid database binding yields a fixed sanitized unavailable warning and no observer/client. Invalid credentials/permissions/preallocation produce a bounded failed auxiliary startup and connection close; native worker proceeds. Initial startup is not retried into a later epoch automatically. Established observers retry individual bounded reads/pulses while retaining their epoch, log each fixed failure category once and cap error counters. Permission/network restoration may resume the same epoch; a lost epoch stops the observer and closes its client. No diagnostic error contains URI/password/exception text. No failure weakens native fencing or triggers a build/recovery.

Rollback design: an operator disables the explicit flag and performs a separately approved service restart; native builds/leases/publication remain the existing2G protocol. No runtime drop of credentials, locks, generations, telemetry history or artifacts is part of rollback. Because native close does not join an in-flight job, production stop/restart timing requires explicit deployment review rather than telemetry-derived safety assertions.
