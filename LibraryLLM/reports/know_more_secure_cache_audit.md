# Know More secure cache audit

Existing auth: Core login/staff-login use the same HS256 JWT signer, numeric user_id/sub, live current_identity role/account checks, reader expiry 60 minutes and staff 30 minutes. No refresh token, sid/jti, revocation or server logout route existed. Frontend stored auth token/user in localStorage and logout deleted these only. Document uploads/list were unauthenticated; book access had separate entitlement checks.

Existing uploads: rag/api.py → DocumentService.extract_pdf (PyMuPDF per page) → clean_text → per-page character windows 3000, overlap400 → embed_chunks (shared all-MiniLM-L6-v2, normalized float32 384D) → shared IndexFlatIP rag/index/rag.index, rag_metadata.json → retriever.reload. Filenames supplied identity; uploads, extracted JSON, chunks JSON persisted in rag/documents, rag/extracted, rag/chunks. Uploaded documents were shared across accounts. There are no Mongo upload metadata/chunk collections in this pipeline; Mongo book_chunks is a permanent Book RAG asset and must never be deleted for logout.

Artifacts: raw PDF SOURCE; extracted page JSON DERIVED; chunks/source metadata DERIVED; float32 vector matrix DERIVED; FAISS IndexFlatIP RUNTIME; registry metadata RUNTIME; document intent cache RUNTIME. No PDF viewer/download on Know More; chunks/page mappings suffice for restored retrieval, so the portable bundle omits original PDF and redundant extraction.

New active artifacts are isolated under rag/private_documents/doc_<random>/ with a SQLite registry. Registry records carry server-derived owner_user_id/owner_session_id and expiry matching JWT exp. sid is added to the existing signer. Shared SQLite revocation permits Core and RAG to invalidate the same session. Legacy JWTs retain book/account compatibility but must re-login for private uploads; legacy ownerless uploads remain inaccessible and are not silently migrated.

The existing DocumentService parser/chunker/embed helpers and all retrieval, reranker, evidence, Qwen prompts, latency adapter and Book RAG files remain unchanged. The HTTP adapter loads only the authorized selected upload into retriever.doc_* inside the existing inference lock and clears it in finally; global/book searches never receive uploads. Assistant conversations now include sid in ownership.

cryptography 50.0.0 already installed and requirements already declare it. AES-256-GCM + HKDF-SHA256 use that library. One 32-byte base64 master key is explicitly configured; no production auto-generation. Bulk ciphertext is binary HTTP, not base64 JSON; only a bounded encrypted descriptor uses base64. OPFS preferred, IndexedDB Blob fallback, no Web Storage document content. Read-only references: https://cryptography.io/en/stable/hazmat/primitives/aead/ and https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/getDirectory .

No dangerouslySetInnerHTML found in frontend/src. Descriptor display is React text. Browser profile/OS compromise, extensions and same-origin XSS during authenticated use remain outside the confidentiality guarantee. Cache copies stay until removed or browser eviction, with explicit bounded quota and manual removal; no silent LRU deletion.
