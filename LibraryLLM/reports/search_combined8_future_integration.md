# V8 future integration changes — unapplied

This is a reviewable integration specification, not an activated implementation or a claim of durable qualification. The exact transport diff remains at `reports/search_proof7_transport_proposal.patch`. Its two hunks widen `search/interaction_api.py::ChoiceRequest.query` and `frontend/src/components/SearchAutocomplete.tsx` from150 to500 without truncation. Suggestions have their own150-character contract; widening ChoiceRequest does not implicitly widen suggestions.

The disabled source implementation to promote only after qualification is frozen in `reports/search_combined8_source_freeze.json`. Its `native_adapter.py`, `recompilation.py`, `completion.py`, `refinement.py` and tests define the source edit contract. Promotion must preserve those hashes or create a separately versioned, requalified candidate. No production module should import scratch code in a released package.

## Required file and function changes

1. `search/query_interaction.py::offer`: store the complete accepted source separately from the latest submitted refinement command. Issue server-owned choice objects equivalent to `native_adapter.IssuedChoice`: requirement ID, domain, operator, authorized source span, original source and digest, full IR digest, parser version, accepted-plan base version, owner/login/library/workspace/mode, expiry and one-use status. Client DTOs must not supply offsets, fields, arbitrary plan values or trust assertions. The current row's `query` alone is insufficient evidence for source-bound edits.
2. `search/query_interaction.py::load_choice`: retain fresh backend authorization and strict owner concealment. Validate the complete stored tuple and compare the request's immutable source, mode and session. Reconstruct current context from authenticated identity/current membership, not request text or a client `authorized` flag. Missing legacy source/IR digests or parser versions require a fresh interpretation; do not silently migrate an existing pending choice.
3. `search/query_interaction.py::transformer`: replace field patching for eligible V8 choices with the exact `native_adapter.resolve_choice` / `recompilation.recompile` contract. Complete only a uniquely owned missing operand. Apply only a uniquely proven source correction. Keep preserves the original uncorrected operand as explicit semantic content, using the frozen source rewrite; it does not pretend that an unsupported negative correction became enforceable. Preserve the submitted command for audit. Reparse the entire resulting source and validate unchanged mandatory condition fingerprints, IR/source/control digests, capabilities and projection. Unsupported or ambiguous edits return422 without committing. EXACT bypasses this semantic edit path.
4. `search/session_store.py::resolve`: after transformation, derive persistence from the reparsed `plan.raw_query`, never the short command originally submitted to the endpoint. Preserve both values. The current `next_row` writes `last_query=query` and a request digest derived before transformation, which cannot by itself establish the accepted-source lifecycle. Proposed additional row fields are:

   ```python
   accepted_source = plan.raw_query
   accepted_source_digest = digest(accepted_source)
   accepted_IR_digest = digest(plan.decision['query_ir_contract'])
   accepted_parser_version = plan.parser_version
   accepted_plan_version = previous_version + 1
   last_submitted_command = query
   # last_request remains an idempotency key bound to command, owner,
   # base version, issued choice and source/IR digests, not a semantic digest.
   ```

   Use the exact frozen `contract.digest` encoding. Persist the full accepted source and plan together. Current `last_query` replay/refinement comparisons must compare against accepted_source, while command replay must use the separate idempotency receipt. Bind the CAS predicate to owner/login/library/workspace, base version, source/IR/parser digests and unexpired current session. No blind retry may rebase a source edit onto a changed accepted plan.
5. `search/query_interaction.py::reservation` and `search/session_store.py::resolve`: atomically fence one-use choice consumption against the accepted version update. Existing reservation/receipt code is a starting point, not proof that a multi-document choice/session commit is atomic or crash-safe. The staging implementation must choose and test a supported Mongo transaction or a single-document atomic receipt/state transition with recovery rules. Do not mark a choice used until the accepted state is durable, and do not allow replay after a durable commit whose response was lost.
6. `search/interaction_api.py::resolve`: preview against fresh authorized capabilities, then obtain fresh authority for commit; retain existing lock ordering. Return the backend-owned `accepted_query`, `source_digest`, `IR_digest`, `parser_version`, `accepted_plan_version` and interaction receipt only after a successful commit. `choice_applied=True` alone is insufficient. Retrieval must use the accepted plan/source with the same trusted library/workspace binding. It must not rediscover scope from source text.
7. Frontend choice consumer: display/store the returned full accepted_query as the search box/session source. Preserve the short user command only as a separate interaction record. Send the full accepted source on the next choice request. Do not slice to150, concatenate conversation transcripts, synthesize source spans or mutate plan fields client-side. Refresh a stale choice on409; conceal foreign choices on404; expire on410; show source-specific unsupported edits on422.
8. Parser/routing promotion: feature-flag the complete V8 parser/proof/ontology/edit bundle together. Preserve C4 as rollback and preserve EXACT native routing. Do not mix V8 decisions with C4 edit assumptions or reuse parser-version-incompatible accepted sessions. No model is selected for this bundle.

## Required separately authorized qualification

Obtain an explicit isolated Mongo namespace and write authorization before seeding or testing. Exercise real JWT/current membership across public/private patron/staff, outsiders and tenant A/B; use session/choice versions plus accepted source/IR digests in stale/replay/expiry/crash tests. Include150/151/500/501 transport boundaries and a completion that crosses150 while staying within500. Verify no operation changes untouched mandatory operands, negation or source ownership.

Test response loss after CAS, process crash at each reservation/commit boundary, concurrent double submission, expired membership between preview and commit, rollback across parser versions and unavailable global metadata. Keep private-owned unlinked retrieval independent of global catalog availability. Linked metadata enrichment must separately check paired catalog/vector generations and failure behavior. Real vectors/relevance/current health and full-search/concurrent platform SLOs remain unqualified. No Mongo write, service configuration change, index rebuild or production activation is authorized by this specification.
