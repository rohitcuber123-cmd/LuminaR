## Decisions from the audit

Extend the shared notification store, bell and existing tenant worker; do not create a parallel notification system. Keep Events API/category/edit/history behavior intact. Introduce only the missing announcement aggregate because its immutable published-content and durable recipient snapshot contract is not provided by the editable event model. Links reference canonical tenant event IDs. Event transitions remain existing workflows; staff may publish an explicit linked-event announcement without a second automatic event broadcast.

Announcement management: ADMIN only, including owner via canonical ADMIN membership. LIBRARIAN has existing Event permissions but no new announcement-management grant. All active eligible institution roles may read published announcements. Visibility uses current membership; recipient snapshot is publication-time membership; no retroactive copies for joiners. Published content is immutable; withdraw and create a new announcement for corrections. No schedules.

Before application edits, capture source/report/data/index/artifact baselines and execute full accepted product backend/frontend inventory. All later claims require actual new results.
