## E–F. Generated-answer failure and isolated verifier

`LuminaRAG.ask` validates **evidence before generation** (`rag/qa.py` around lines 764–795), generates the answer later (around line 840), then attaches selected sources (around line 862) without checking the generated proposition. `rag/citation_boundary.py` checks page attribution, not factual consistency. Thus native Qwen can return `SUPPORTED` for 61 minutes = 3660 seconds, generate `No`, and still receive a source citation.

`evaluation/generated_answer_verification.py` is an **isolated pilot, not a production QA integration**. Its inputs are the original question, already authorized passages, generated answer, cited chunk IDs, and an optional selected source ID. It extracts bounded explicit assignments and yes/no propositions, requires matching entity and field, checks exact identifiers/dates, polarity, numeric identity, and deterministic hour/minute/second equivalence. Contradictory or missing support yields `CONTRADICTED`; explicit limitation language yields `ABSTAINED`; unparsed or ambiguous claims yield `UNKNOWN`. A cited ID outside the supplied authorized set or an evidence item from a different selected source is rejected. The caller remains responsible for upstream authorization of the selected private/institution source. No model answer is rewritten, no retry is attempted, and no parallel QA pipeline is used.

An eventual integration must be reviewed at the exact `rag/qa.py`/citation interface. Within the bounded explicit-fact scope, only `VERIFIED` may keep supported citation entitlement; `CONTRADICTED` must suppress citations and use the existing conservative failure response. `UNKNOWN` cannot be presented as verified. The current QA contract does not establish a safe regeneration loop, so no retry is proposed. Broader free-form answers need a separately validated strategy; the pilot is not general entailment.
