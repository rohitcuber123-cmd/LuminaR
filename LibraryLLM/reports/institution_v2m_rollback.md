# Rollback contract and qualification

Rollback changes only the optional observer configuration at a separately controlled worker restart. It does not roll back native jobs, generations, catalogue data, barriers or published pointers. The existing nonjoining native close can leave an in-flight build running until it exits, so an operator must arrange a quiet native-safe window using canonical job state and existing deployment ownership. No automatic drain/cancel/control feature is added.

The disposable rollout runs disabled native behavior, explicit enabled idle/Search/KG, a new equally restricted writer principal and a fresh worker epoch, then a disabled restart. The disabled restart must leave jobs, generation rows, barriers, target pointers, artifact bytes and the retained telemetry singleton exactly unchanged. Subsequent manually requested disabled Search/KG builds must complete with valid native publication; older rows and artifact bytes remain retained and their current target artifacts are validated. The focused rollback test also compares each retained document by_id across new legitimate work.

Operator-owned future steps: record canonical active/previous generations and job/fence/lock state; coordinate a period with no new build submissions; disable LUMINAR_WORKER_TELEMETRY_ENABLED in the approved launch context; stop/restart only the verified owned Search service through its existing procedure; verify no auxiliary observer/client is created and the normal native worker remains available. Reader diagnostics should honestly show old/stale/STOPPING/STOPPED evidence, not invented current health. Request only an explicitly authorized disposable smoke build if the operator scope permits it; no automatic rebuild is part of rollback.

Do not clear a tenant lock, delete a generation or retained artifact, rewrite a completed job, change last-good references, cancel an active build, relax a lease/fence or use the read-only CLI for mutation. Uncertain native outcomes remain subject to the existing manual Library Admin reconciliation/recovery path. Any expiry injection/manual recovery in failure fixtures is explicitly labelled test work and is not the rollback action.

Production rollback is not certified until service ownership, secret delivery, authentication hardening, native-safe restart/coordination and representative operational behavior are qualified. No production rollback, service restart, secret change or activation was performed in Part2M.
