# Personal document separation

Accepted personal uploads remain account/session owned in `rag/private_documents/registry.sqlite` and `doc_<opaque_id>` directories. The existing private document service checks session identity, JWT expiry/revocation, owner, ACTIVE state and document expiry. Personal upload, list, detail, local device cache, export/restore, Knowledge Tools and logout cleanup retain their existing routes and ownership. Part 2F does not copy personal metadata into the canonical library asset collection or infer a library from the uploader's current memberships.

Library-owned assets use independent `institution_library_assets` and `institution_library_asset_jobs` records with explicit library/asset UUIDs. Storage lives in the separate ignored `local-data/library-assets` root. Each source, generation, extraction, chunk, FAISS index and Knowledge output is scoped to that explicit ownership. The original filename/global work reference does not confer global or personal ownership. Personal cache export/restore does not accept library artifacts, and a library upload does not add a document to the personal session registry.

Staff Digital Assets and Patron Resources enter explicit library routes. Authorized document Q&A and supported Knowledge Tools operate on one selected canonical asset; global Assistant does not automatically search memberships. Future execution rechecks live membership and visibility instead of treating an earlier selection as a durable grant. The new library interface has no personal-to-library sharing/promotion action and no cross-document tenant semantic search.

`scripts/migrate_library_assets_v2f.py` is a read-only historical inventory and explicit mapping review tool. Personal session records remain PERSONAL_PRIVATE. Flat legacy documents without canonical proof are LEGACY_AMBIGUOUS/AMBIGUOUS_DOCUMENT_OWNERSHIP. Existing permanent per-work artifacts retain their Book RAG classification; no filename or uploader's membership assigns them to a library. The tool reports historical storage counts without document text or credentials. A proposed explicit mapping requires canonical ACTIVE library, bounded ownership evidence and source-owner consent to become reviewable; it remains unapplied.

Automatic migration count and personal-document modifications remain zero. Applying historical sharing/transfer is deliberately unsupported in this phase: it requires a separately reviewed ownership transfer and retention process. No production account grants, personal document deletion, personal corpus reindex or global HNSW/KG changes are part of these adapters.
