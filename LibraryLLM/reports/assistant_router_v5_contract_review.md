# Frozen V5 contract review

The registry has 29 action meanings and five exemplars per action (145 total), plus bounded position/field/criterion banks. Meanings and exemplars were sealed before evaluation/DEV authoring. There is no optimization of exemplars against test results, classifier fitting, fine-tuning or regex intent dictionary. This is a coding-agent review, not an independent human sign-off.

Current loans explicitly require active/unreturned borrowing; history covers past/completed activity. Holds/reservations are existing account state; placing a reservation is a confirmed mutation. Fees are outstanding monetary obligations; topic finance requests belong to Search. Reading-list viewing and its three mutations remain distinct.

Search preserves the original request. Personalized suggestions have no seed, single-seed and multi-seed recommendations use the existing recommender, and More Like This uses one graph seed. Available alternatives add a current-stock constraint. Structural eligibility removes a multi-seed contract when fewer than two books are bound. These close meanings remain an empirical routing risk.

Factual comparison describes differences without a winner; field comparison names a supported objective attribute; preference comparison chooses suitability and may need a reading purpose. Rating average and rating count have separate field references. Undefined preference criteria clarify deterministically rather than inventing a purpose. A clearly supplied purpose is interpreted by the existing Qwen while server-bound identities remain intact.

Availability checks are read-only; borrowing, return and reservation remain confirmation proposals in the executor. All mutation contracts set a confirmation flag. Cached-decision replay exposed a boundary: the legacy reading-list add/remove executor ignores that flag and performs the reversible write immediately; clear requires its explicit UI action. No real reading-list operation is performed by that replay. Metadata requests differ from content questions. Document and Book RAG contracts require the corresponding server-side capability; final source authorization stays in the existing tools.

Continuation requires a current paginated result. Refinement requires an existing result basis and useful bounded filters; missing author/sort values clarify. Some sealed/DEV refinement labels request an unspecified author/order and are intrinsically underspecified. They are retained and counted as strict failures rather than repaired after sealing.

Named-title extraction is separate from action selection and must copy a literal span. The existing generic-referent guard, invented entity text, extra model work-ID fields and extracted titles shorter than three characters are rejected. The length guard is conservative and can reject legitimate short titles. Sealed review found five contextual/non-entity spans that bypass the generic guard; literal presence alone cannot validate a named book. Unknown entity names alongside a single contextual book remain a risk: semantic scoring alone is not a general entity recognizer. These failures are retained, with no post-seal patch.
