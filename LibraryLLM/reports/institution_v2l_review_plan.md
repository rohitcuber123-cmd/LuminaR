# Review-first native integration boundary

Source authority is the current native worker/store/startup, J authentication/diagnostics and all K primitives/harness/results discovered from K changed_files.json. Native claim, renewal, store.progress and publication order stay authoritative. No telemetry control edge is allowed. K currently hard-restricts writer/reader to fixtures and wraps global store.claim only inside child experiments; that adapter is not a native seam. Native close signals stop/cache clear without a join. The installed Search API starts the tenant worker only when both resident embedding model and reranker exist.

Baseline is captured before integration edits, including exact existing source/report hashes, production tenant state/artifact metadata, collection/index contracts and Git state. Fresh frozen baseline suites through K run before native/K files change. New review/harness/shared-module files can be prepared independently while they run.

Promote the K Actor/Agent and bounded read implementation into canonical backend service modules, retaining thin fixture-restricted K compatibility facades and unchanged K tests/reports. This is one implementation, not a second telemetry system. Keep the same fixed collection, singleton, schema, current/previous8 entries and16384-byte bound. Preserve J authentication and CLI unmodified; add only a separate bounded read-only supplement using that same principal. No public/Staff endpoint or frontend change.

Native integration: one optional factory per TenantIntelligence instance, disabled by default. Start owns at most one observer/thread; trusted hooks are nonblocking context hints only after acknowledged claim/progress and after native outcomes. The auxiliary thread re-reads accepted durable tuples with owner/fence checks and records server observation time, never intended transition/commit time. Native lease90s/renewal10s/idle2s and serial builds remain unchanged. Shutdown keeps native nonjoining behavior; only the auxiliary thread has a bounded join and best-effort STOPPING/STOPPED evidence. An in-flight native build may outlive telemetry; no false STOPPED or publication acknowledgement may result.

A dedicated explicit enable flag and separate writer URI are required. Missing/invalid credentials produce sanitized unavailable diagnostics without falling back to MONGO_URI, operator credentials, JWT or application roles. Exactly scoped server-effective privileges are verified. No production provisioning, activation or deployment action is authorized. Disposable auth-enabled mongod fixtures alone provision the singleton, validator, restricted writer/read operator/unauthorized identities. Namespace validation/secret ownership remains a deployment review responsibility.

Validate single-observer ownership, repeated start/close, no healthy/process claims, late epoch rejection/termination, connection/auth/timeout/observer faults, accepted progress deduplication, and genuine native Search/KG/crash/restart/A-B-C queue behavior without monkeypatching native methods. Benchmark frozen native baseline versus integrated disabled/enabled in equivalent fixtures, measure idle/build/start/stop/thread/connection/write/storage costs, then run all final frozen groups/front/build/lint and preservation. Report deployment NOT_QUALIFIED unless actual deployment ownership/supervisor prerequisites are established; fixture success alone is insufficient. Stop after2L.
