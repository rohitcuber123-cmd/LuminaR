# Negative constraint ownership

The inherited text-negative recognizer omitted WITHOUT even though the production whole-word predicate supported it. The explicit negative operator family now includes WITHOUT and BUT NOT, preserving the same normalized term and word boundaries used by native matches. Category exclusions go to exclude_subjects; format exclusions go to excluded_formats; searchable text goes to exclude_terms. Unsupported field-specific author/title negation is represented and blocked, rather than becoming a positive entity or a broader text predicate. Negative availability retains the established typed unsupported/conflict behavior.

Pipeline: source owner/operator → source-bound Candidate → Requirement + domain state → QueryPlan exclusion list → native matches after hydration. Production word normalization and `(?<!\w)` / `(?!\w)` boundaries remain unchanged; Marsh/ar tests pass.
