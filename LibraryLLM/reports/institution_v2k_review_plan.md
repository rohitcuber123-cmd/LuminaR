# Reviewed 2K prototype boundary and safety gates

Source audit precedes telemetry implementation. Existing `TenantIntelligence.start → loop → run_one` runs one daemon serially. Claim uses the durable tenant barrier, unique effective-active target job, fresh worker fence and 90-second lease; renewal is a separate ten-second thread. Native `store.progress` updates acknowledged stage/state/counters, but no progress time. Final publication validates, renames privately built files, checks native lease/Admin/source under barrier, updates the fenced pointer, then acknowledges the job. `close` sets stop and clears cache; it does not join an in-flight build. Existing public APIs and Part 2J local read-only CLI are frozen.

The initial design is a **fixture-only isolated prototype**, not a production observer. Identity is generated UUID4 plus monotonic telemetry epoch and private boot nonce digest; no PID claim. A preallocated singleton auxiliary collection stores current and previous lifecycle, at most eight recent per-job progress observations per instance and a maximum BSON size. No TTL/deletion or unbounded event journal. Mongo server $$NOW supplies observation times; inconsistent/future/rollback evidence stays UNKNOWN. A recent pulse proves a successful self-report, never PROCESS_VERIFIED_ALIVE or HEALTHY.

Use an auth-enabled disposable mongod, separate collection-limited telemetry writer (find/update telemetry, find jobs/targets only), ordinary unchanged native fixture writer, and unchanged database-local Part 2J read principal. Verify actual server-denied writes to jobs/targets and operator-denied writes. No production account, index, collection, privilege or secret is provisioned.

Independent auxiliary thread pulses while idle/building; it must never renew native leases, claim, publish or recover. Progress observations come from primary Mongo **after** accepted durable native tuple changes and are validated against captured internal claim/fence/owner. Identical tuples and lease heartbeats do not advance progress time. Failed/unknown outcomes are distinct from successful progress. SUCCEEDED requires native acknowledgement plus matching published-by-job/generation/source. Timestamp means post-read observation, not an invented precise native commit timestamp. Reader independently correlates current job/fence/tuple; lag or changed ownership is UNKNOWN.

Resource design: candidate pulse ten seconds (six idle writes/minute excluding lifecycle); active observer polls at bounded intervals and coalesces changes rather than writing per inference. Bounded deadlines, no blocking telemetry network work in native callbacks, bounded failure counters/log codes, best-effort shutdown only after native thread actually ends. Failure to join must not emit STOPPED. Auxiliary failure never weakens mandatory native checks.

Native qualification will use the actual resident worker, cached offline MiniLM/FAISS and actual KG builder, authenticated fixtures, private libraries, build API, restarts, progress/lease separation, handled failures and genuine child-process termination. Fault/race/storage/clock/auth cases and paired overhead measurements must precede any production decision.

Production integration gates: a reviewed per-instance lifecycle/observer seam in native worker (process-global instrumentation is not production safe), deployment-authenticated restricted writer and OS secret controls, complete native causal/race/crash evidence, bounded startup/shutdown/failure overhead and representative performance. Until those pass, no existing runtime or Part 2J CLI/allowlist is edited. Prototype command accepts only its explicitly named fixture database namespace. A missing gate yields PARTIAL and prototype-only delivery, not silent activation.
