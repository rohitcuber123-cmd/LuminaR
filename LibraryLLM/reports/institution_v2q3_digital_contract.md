# Part 2Q.3 digital availability contract

The original defect crossed three boundaries: Qwen could label a digital question as CHECK_AVAILABILITY; LibraryCatalogue.project and Book retain physical stock but discard format/resource metadata; ground_operational_message and the card badge render those counts as availability. No fresh digital authorization lookup existed in that response path.

The fix keeps Qwen's canonical scope, positions, finite ID decoding and the original resolver. A narrow request-modality boundary directs digital-access questions to a fresh Core lookup, even when the parsed intent says stock or content. It does not choose a different book. Content topics such as digital networks and online fraud retain their ordinary routing. Explicit physical actions remain physical unless their request explicitly asks about digital access. No document text or private resource metadata is sent to Qwen for answering availability.

Core uses existing membership, catalogue, asset and reader services. There is no new persistence, storage architecture or parallel application database. Disposable databases are test infrastructure only.

| Fact | Authority and meaning |
|---|---|
| Catalogue present | Current canonical book exists in the effective scope; a Global record cannot stand in for a local holding. Missing/foreign local books fail before asset lookup. |
| Physical copy count | Existing Book.total_copies and Availability.total_copies. |
| Physical available count | Existing holdings/requestability projection, unchanged. |
| Digital resource link present | A canonical reading/resource route was returned from verified evidence; never generated by Qwen. |
| Digital asset present | True only for an authorized verified source; UNKNOWN uses null to avoid revealing hidden asset existence. |
| Digital asset access authorized | Current membership/private-code eligibility, role, asset visibility, READY state and existing file/artifact checks pass. |
| Full text accessible | The existing reading/file authority permits the source at check time. Opening it repeats authorization; it is not a permanent entitlement. |
| Digital availability unknown | No sufficiently verified source for this account. This does not assert that no digital version exists anywhere. |

Tenant lookup uses the exact library UUID and canonical library_book_id, bounded visible linked assets and the same authority barrier as catalogue reads. It checks existing source/artifact paths through authorize_asset(ready=True), then rechecks membership. It never uses global_work_id to discover a tenant document. Hidden, incomplete or missing sources produce UNKNOWN without asset IDs, titles or links. Global lookup uses the existing reader entitlement and readable text registry, never institution assets.

The existing services expose no reliable external full-text entitlement contract. An arbitrary online_url or a PDF-looking URL therefore cannot become an accessible document. Such data returns explicit UNKNOWN rather than inferring resource type, reading rights or a download link. External-link presentation beyond a verified canonical service signal remains outside this change.

DigitalAvailability is a strict typed result, separate from physical Availability. Tool validation rejects foreign book/library evidence and noncanonical resource targets. Authorized targets can only be existing library resource or Global text reader routes. Qwen prose is skipped for these facts. The deterministic renderer names the actual resource type, and the frontend shows Open PDF/Open digital text while suppressing the physical-stock badge on digital response cards. Normal physical responses keep the original rendering. Existing RAG answers and citations are unchanged.

All earlier failed fixture/setup attempts, concurrent-read 503s, sequential rechecks, model refusals and final suite results remain separate evidence. No frozen assertion or authorization guard is disabled.
