# LuminaR Router V5 architecture

V5 is an explicit `ASSISTANT_ROUTER_MODE=router_v5` experiment. The default remains `existing_qwen`. V3/V4 source, models, datasets and evidence are preserved by the 3,426-file V5 baseline manifest. No classifier is trained and no model is downloaded.

The request-local binder first chooses identities using structured action arguments, reliable literal book names/IDs, current selection, active prior comparison/recommendation, page and recent results/focus. An explicit empty active result does not resurrect stale references. Selection changes discard stale focus. This step runs before semantic scoring. Actual IDs, private source identifiers and account facts do not enter the CPU worker; public book titles/positions enter the Qwen fallback only.

The frozen registry has 29 action contracts, each with a semantic definition, five curated exemplars, negative notes, context/argument requirements, existing public intent mapping and confirmation flag. Separate six-position, six-field and two-criterion banks are small static semantic references. Authorized document/book capabilities eliminate impossible content-source contracts. Core permission checks and existing RAG ownership enforcement remain authoritative.

One spawned CPU worker loads the cached frozen MiniLM once, precomputes static contract embeddings and processes a bounded queue of opaque request tickets. Cancellation retains its slot until the worker replies. A request-local future receives only its own ticket. The selected retrieval aggregation is 70% maximum exemplar similarity, 20% average of the three closest exemplars and 10% definition similarity. Per-action score and top-two margin thresholds are calibrated on DEV only. Auxiliary matching has separate thresholds. Mutation admission is stricter. Borrow/return/reserve retain executor confirmation. Reading-list contracts also set a confirmation flag, but the unchanged legacy executor does not enforce that flag for add/remove; clear requires its explicit UI action. The flag alone is not a product safety guarantee.

The cached [CrossEncoder L6](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2) is Apache-2.0 and trained for MS MARCO query/passage relevance. It is not an entailment classifier. Both top-three pair-verification forms were measured on CPU. Neither passed the required 20-request p95 below one second, so the candidate has no permanent verifier. No compact NLI model is downloaded or benchmarked.

The selected MiniLM worker uses batches of at most eight with a 5 ms collection window. Accepted routes never call Qwen or acquire its inference lock. Uncertain requests give the existing Qwen only the top four eligible meanings plus bound public context, with one routing call and no retry. Qwen can select an action, bounded position/field and a literal current-message criterion or title span; it cannot choose IDs or a different context source. Search receives the original message. Missing criterion yields deterministic `CRITERIA_AMBIGUITY`; positive/free-form criteria use fallback. Filter refinement requires bounded, literal argument extraction.

The existing lifespan HTTP client is retained: forty maximum connections, twenty keepalive connections, request-specific bearer headers and no per-request AsyncClient construction. Search, Recommendation, KG, RAG algorithms, frontend and Admin/Notifications are unchanged.

Construction order is recorded in separate seals: registry meanings, 168-case evaluation, separate 244-case DEV, thresholds and candidate, then one sealed run. Old 116/121 sets are exposed regression evidence. The new pack is hash-sealed but is not perfectly independent: this coding agent authored the manual cases, and some context variants share an utterance. The independent offline existing-Qwen generation received scenarios, not exemplars; malformed/ambiguous outputs and invented named books were rejected before sealing. The previous/changed/recommendation and short-turn strata are modest; subgroup counts must accompany accuracy.
