# V2C-C resume benchmark protocol and outcome

Fresh security preflight passed before benchmark work:110 isolated cases plus live API/Mongo workspace denial, forged-then-genuine clarification, actual revocation and outsider denial. Historical C/C1/B1 reports were archived before updates; C1 and B1 historical reports remain unchanged.

Version V2C-C-resume-1 contains7112 case-context rows,6528 unique query texts and72 families. Composition:612 independently authored AI-reviewed core rows,2000 polite-framing/paraphrase variants,1000 noisy framing/punctuation variants,750 contradiction/negative variants,750 ambiguous/incomplete variants,1000 multi-constraint variants,500 entity/number protection variants and500 native security/scope variants. Generated6500 remain UNREVIEWED. Shared query text may represent different workspace, mode, actor or native action. Framing derivatives are not independent natural-language samples or comprehensive word-order coverage.

Original540 rows,530 unique texts,54 families and320/110/110 split files remain byte-identical. An independent output-blind agent reviewed540 originals in a separate overlay and authored72 additional core rows in18 meaningful families. Each family and derivatives remain in one split. Expanded counts:4094 development,1611 calibration,1407 heldout. Original holdout manifest is archived and embedded in the expanded manifest. Original authoring source is unchanged.

Independent review flagged37 development,30 calibration and12 heldout originals for uncertainty, native context, generation cautions or exposure; not all flags are label errors. Two contextual exact-text groups overlap splits. Main agent inadvertently saw10 originalh11 source rows during source inspection. Those rows were not used for generation or tuning; no claim of wholly unseen holdout. No heldout evaluation occurred. Sealed generation processed heldout rows without printing labels or parser outputs.

Gold never derives from parser outputs. Framing preserves parent labels, operators, negation and protected spans, but every derivative has not been individually reviewed. Exact-mode originals are excluded from prefix transformations. IDs and generated query-context keys are deduplicated. Native/stateful rows require native execution and cannot enter parser-only metrics. Family/scope coverage is explicit; native coverage is incomplete.

Schema adapters fixed before evaluation:semantic/exact mode names map to SMART/EXACT; unspecified sort maps to RELEVANCE; absent semantic text maps to empty text; scalar soft preference maps to a list. No expected semantic label is copied from parser output. Exact match includes labelled slots, decision, execution eligibility and affected unsupported/incomplete/contradiction fields. Normalization preserves technical punctuation; token F1 distinguishes C++,C# and C.

Hard precision/recall compare enforced atoms with comparator exclusivity. False hard filters compare actual enforced atoms against textually justified gold atoms even on blocked gold. Unsafe auto-parse means executable blocked gold with invented hard atoms, an executed contradiction, or silently dropped unsupported strict metadata. Safe literal typed-decision misses are separate. These definitions were fixed before parsing. Rates contain numerator/denominator; token F1 is sum of per-case F1/count. Plan vocabulary leakage and actual content leakage have separate populations. Parsing cannot establish lifecycle safety.

Sources and labels were frozen before first development evaluation. Only development file was opened by evaluator:3742 parser cases evaluated;352 development native cases unexecuted. Mandatory thresholds failed and work stopped. No parser tuning, calibration, heldout, optional model or final browser acceptance followed. Raw observations were not rerun or relabelled.

Draft remains unaccepted. Results are diagnostic against normative, partly unreviewed labels, not a count of confirmed production defects or an unbiased real-world accuracy estimate. Label/representation cautions require independent future adjudication, without changing this frozen result to improve scores.


Closure audit:raw files contain7112 rows with unique IDs, but mode-alias normalization revealed7 duplicate query contexts. Effective counts are7105 unique cases (4087 development/1611 calibration/1407 heldout),611 distinct AI-reviewed core cases and6494 distinct unreviewed derivatives. Annotated stored counts remain612/6500; human review0. Unique paraphrase/noise categories are1996/998, short of2000/1000. The dataset therefore fails category/dedup quality gates in addition to parsing gates. See search_v2c_c_resume_duplicate_audit.json. Corpus and first-evaluation data were not regenerated or rescored after discovery; the raw3742-row development metrics include the7 duplicates and are provisional, not unique-case accuracy. A future benchmark version must normalize mode aliases before generation. Active Search continues appending its existing C1 stdout journal; archived historical snapshots and structured C1/B1 evidence remain preserved.
