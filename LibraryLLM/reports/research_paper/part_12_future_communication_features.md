# Part 12 — Future institution communication features

Status vocabulary: IMPLEMENTED_VERIFIED requires executed evidence; IMPLEMENTED_NOT_VERIFIED means code is present without complete executed evidence; IN_PROGRESS is active unfinished work; PLANNED is a possible follow-up; NOT_IMPLEMENTED means absent. No feature below is newly implemented by Part2P merely because this roadmap describes it. Existing partial capabilities are explicitly identified.

| Feature / current status | User value | Backend + database dependencies | Frontend work | Privacy / failure risk | Complexity and experimental evaluation |
|---|---|---|---|---|---|
| Scheduled announcements — NOT_IMPLEMENTED | Publish at an appropriate time | Durable scheduler, timezone contract, cancelable scheduled state, idempotent publication and due index | Timezone-aware schedule/preview/cancel | Accidental early publication; DST ambiguity; revoked publisher | High; clock-skew, restart and duplicate-trigger experiments |
| RSVP and attendance — NOT_IMPLEMENTED | Capacity and participation planning | Canonical event registrations, capacity CAS, waitlist policy, attendance retention | Register/cancel/attendance views | Participant disclosure and coercive attendance tracking | High; oversubscription races and fairness tests |
| Automated event reminders — NOT_IMPLEMENTED | Reduce missed events | Supported scheduler and per-event/recipient/reminder dedupe; cancelled-event suppression | Reminder policy/status | Sending after cancellation or membership loss | Medium/high; failure injection at trigger and send boundaries |
| Email — NOT_IMPLEMENTED for announcements | Reach inactive web users | Approved provider, verified address, unsubscribe, retry/dead-letter, deliverability records | Preferences and delivery status | External disclosure; bounced or recycled addresses | High; consent/withdrawal and delayed delivery evaluation |
| Browser push — NOT_IMPLEMENTED | Timely background awareness | Service worker, subscription keys, provider integration and revocation | Permission prompt and subscription management | Shared-device lock-screen leaks | High; expiry, revocation and offline tests |
| Mobile push — NOT_IMPLEMENTED | Mobile reach | Mobile app/token lifecycle and provider credentials | Native settings and safe deep links | Device ownership changes and metadata exposure | High; token rotation and tenant-switch tests |
| Notification preferences — NOT_IMPLEMENTED | Reduce noise | Per-user/library/type preference document; mandatory-message policy | One unified settings surface | Preference inference and failure to honor opt-out | Medium; preference-update versus fan-out races |
| Department audience — NOT_IMPLEMENTED | Relevant institutional messages | Canonical department directory and audited membership assignments | Authoritative audience picker | Sensitive affiliation disclosure; stale assignments | High; cross-department isolation tests |
| Course audience — NOT_IMPLEMENTED | Course-specific coordination | Course/enrollment authority and lifecycle synchronization | Course picker and enrollment explanation | Student record disclosure and stale enrollment | High; semester rollover and revoked-enrollment tests |
| Targeted groups — NOT_IMPLEMENTED | Focused communication | Audited group authority, membership snapshots and permission policy | Group management, audience preview/count | Arbitrary user-ID targeting bypass | High; group-edit/publication concurrency tests |
| Due-date reminders — existing account reminder code | Support timely returns | notification_service.scan_due and existing worker; institution-specific lending semantics need separate review | Existing bell; preferences could extend it | Old due dates after renew/return; private title exposure | Medium extension; reuse current reconciliation tests; do not claim new2P implementation |
| Overdue notifications — existing account reminder code | Explain overdue state | Existing scan_due/loan_notification_service reconciliation; tenant loan adaptation not assumed | Existing bell with policy refinements | Stale debt or loan information | Medium extension; return/renew boundary tests |
| Reservation-ready alerts — existing Part2D tenant notices | Timely collection | Existing committed lending journal/outbox and RESERVATION_READY; external channels remain absent | Existing reservations and bell | Incorrect recipient or queue generation | Existing in-app path retained; extend only with new channel consent tests |
| Weekly activity digest — NOT_IMPLEMENTED | Summarized engagement | Scheduler, bounded aggregation, opt-out and digest dedupe | Preview and frequency settings | Profiling/reading-history disclosure | High; aggregation correctness and privacy-budget evaluation |
| Closure notices — existing Event CLOSURE category | Explain service disruption | Existing Events model; optional future richer calendar/acknowledgment policy | Existing event UI; new announcement can explicitly link event | Overstated emergency scope | Small current reuse, medium future policy; date/withdrawal test corpus |
| Emergency broadcast — NOT_IMPLEMENTED | Urgent institution communication | Explicit governance, exceptional-role approval, provider capacity and escalation policy | Accessible urgent presentation without coercive patterns | Privilege escalation, panic, external disclosure | Very high; authorization review and fail-safe operator exercises |
| Personalized event recommendations — NOT_IMPLEMENTED | Discover relevant programs | Event features, consented profile, tenant filtering, offline relevance evaluation | Optional recommendations and explanation | Sensitive interests and cross-tenant ranking leakage | High; relevance/diversity versus privacy evaluation |
| Academic calendar — NOT_IMPLEMENTED | Consistent institutional scheduling | Approved calendar source, timezone mapping, provenance and conflict policy | Calendar import/preview | Publishing private academic records | High; malformed-feed, timezone and duplicate-event tests |
| Event analytics — partial generic analytics only | Understand program use | Define event-specific aggregate metrics and minimization; Part2E analytics is not evidence of RSVP analytics | Aggregate dashboard with suppressions | Reidentification of small groups | Medium/high; small-cell suppression and accuracy tests |
| Announcement engagement — NOT_IMPLEMENTED | Evaluate communication reach | Explicit consent/retention policy and aggregate views; read_at alone is not proof of comprehension | Aggregate reach dashboard with clear definitions | Individual surveillance and misleading engagement claims | High; distinguish delivery/read/open/comprehension and evaluate bias |

Priority is an optional future roadmap, not authorization to build these features. First evaluate the measured2P delivery behavior and the20,000-recipient ceiling. Larger institutions would require a reviewed paginated durable snapshot design. No automatic new phase, external service, infrastructure worker, telemetry, email/push, global rebuild or production security change is authorized.
