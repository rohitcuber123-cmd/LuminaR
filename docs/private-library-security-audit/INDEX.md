## 2. Core Architectural Principles of LuminaR Multi-Tenancy

1. **Hybrid Multi-Tenancy**: Shared MongoDB collections partitioned by `library_id` for relational bibliographic and circulation data; dedicated physical filesystem folders and separate FAISS indexes for dense vector search and digital PDF assets.
2. **Decoupled Identity & Dynamic Authority**: JWTs encode account identity (`sub`) and session (`sid`), but zero tenant authority. Institutional permissions are queried dynamically from MongoDB on every request, ensuring immediate revocation without waiting for token expiration.
3. **Information Concealment**: Unauthorized access to private libraries or digital assets returns `HTTP 404 Not Found` (rather than 403), preventing enumeration of confidential institutional collections.
4. **Dedicated Vector Retrieval (No Recall Starvation)**: Avoided naive global shared vector indexes. Each library queries exclusively its own FAISS index ($100\%$ candidate scoping), protecting CrossEncoder rerankers from foreign document exposure.
5. **Ephemeral RAG Memory Scrubbing**: Local `Qwen2.5-3B-Instruct` inference runs under mutual exclusion (`engine.inference_lock`), loads only the single authorized document into retriever memory, rechecks authority before and after inference, and scrubs all memory in a mandatory `finally: clear_runtime()` routine.
6. **Programmatic Query Boundary (`TenantInventory`)**: Prevents cross-tenant query injection at the repository layer by intercepting mismatched predicates and forbidding mutation of tenant identity fields.
