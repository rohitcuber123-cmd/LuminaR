# 58. Ablation Study Plan

## 1. Overview and Purpose

Ablation studies isolate the individual contribution of architectural components, algorithmic modules, and design choices within the LuminaR system. In academic information retrieval and retrieval-augmented generation (RAG) literature, claims regarding overall system performance are defensible only when the marginal utility of each component is empirically quantified against rigorous ablations.

This document establishes the systematic ablation plan for LuminaR across four foundational subsystems:
1. **Search & Retrieval Pipeline**: Quantifying the marginal value of cross-encoder reranking, lexical-fuzzy candidate merging, dynamic candidate pool expansion, and vector index approximation.
2. **Generative RAG & Hallucination Defenses**: Quantifying the effect of structured grammar constraints ([lm-format-enforcer](file:///d:/SDC/rag/generation.py)), explicit negative refusal prompting, intent classification routing, and 4-bit NF4 quantization.
3. **Multi-Factor Recommendation Engine**: Quantifying the impact of temporal exponential decay, real-time availability gating, collaborative filtering signals, and composite weight calibration.
4. **Knowledge Artifact Extraction**: Evaluating deterministic NLP heuristics vs. unconstrained generative prompting for mind maps, flashcards, and Cloze generation.

## 2. Search & Retrieval Ablation Protocol

### 2.1 Subsystem Architecture Overview
The full LuminaR search pipeline operates as a two-stage hybrid retrieval system:
$$\text{Full Search Pipeline} = \text{Query Normalization (NFKC)} \rightarrow \left[\text{HNSW Dense Retrieval} \oplus \text{SQLite Lexical Fuzzy Matching}\right] \rightarrow \text{Score Normalization} \rightarrow \text{Cross-Encoder Reranker}$$

Where:
- **Dense Retreival**: 384-dimensional dense vectors generated by `sentence-transformers/all-MiniLM-L6-v2`, indexed in `faiss.IndexHNSWFlat` ($M=32, efConstruction=200, efSearch=128$).
- **Lexical Matching**: SQLite B-tree index over normalized titles, authors, and subjects with fuzzy Levenshtein expansion ([search/lexical_store.py](file:///d:/SDC/search/lexical_store.py)).
- **Candidate Pool**: Top-50 candidates ($k_{\text{retrieve}}=50$) retrieved from the hybrid union.
- **Reranker**: `cross-encoder/ms-marco-MiniLM-L-6-v2` scoring query-document pairs in batches of 16 ([search/cross_encoder.py](file:///d:/SDC/search/cross_encoder.py)).

## 3. Generative RAG & Hallucination Defense Ablations

### 3.1 Subsystem Architecture Overview
The LuminaR RAG pipeline combines retrieval with constrained local language modeling:
$$\text{User Query} \rightarrow \text{Intent Router} \rightarrow \text{Context Retrieval} \rightarrow \text{Context Packaging} \rightarrow \text{Constrained Decoding (Qwen2.5-3B-Instruct)} \rightarrow \text{Output Parsing}$$

Key defensive mechanisms:
1. **Structured Schema Enforcement**: `lm-format-enforcer` intercepts token logit distributions at decoding time, masking tokens that violate regular expressions or Pydantic JSON schemas ([rag/generation.py](file:///d:/SDC/rag/generation.py)).
2. **Negative System Refusal**: Explicit system prompting instructing the model to emit `"NOT_SUPPORTED"` or abstain when the retrieved context lacks grounding facts.
3. **Intent Classification Routing**: Pre-generation classification separating catalog queries, factual Q&A, and off-topic requests.
4. **4-Bit NF4 Quantization**: `bitsandbytes` NF4 quantization enabling execution of `Qwen2.5-3B-Instruct` within 4GB VRAM.

| :--- | :--- | :--- | :--- | :--- |

## 4. Recommendation Engine Ablations

### 4.1 Subsystem Architecture Overview
The LuminaR multi-factor recommendation engine computes candidate ranking scores using an 8-factor composite formula ([services/recommendation_service.py](file:///d:/SDC/services/recommendation_service.py)):
$$S(u, i) = \sum_{k=1}^{8} w_k \cdot f_k(u, i) \cdot \mathbb{I}(\text{available}(i))$$

Factors:
1. $f_1$: Subject/Genre affinity ($w_1 = 0.25$)
2. $f_2$: Author affinity ($w_2 = 0.20$)
3. $f_3$: Embedding semantic similarity ($w_3 = 0.20$)
4. $f_4$: Global popularity / checkout volume ($w_4 = 0.10$)
5. $f_5$: User rating / catalog review score ($w_5 = 0.10$)
6. $f_6$: Temporal recency decay: $e^{-\lambda \Delta t}$ ($w_6 = 0.05$)
7. $f_7$: Collaborative co-borrowing pattern ($w_7 = 0.05$)
8. $f_8$: Catalog diversity penalty (intra-list distance) ($w_8 = 0.05$)
$\mathbb{I}(\text{available}(i))$: Binary availability filter (copies available $> 0$).

### 4.2 Recommendation Ablation Matrix

| Ablation ID | Configuration Name | Modifications / Component Removed | Mechanism & Operational Flag | Target Measurement |
| :--- | :--- | :--- | :--- | :--- |
| **ABL-REC-00** | **Full Composite Engine** | None (Reference baseline) | Full 8-factor formula with availability gating and exponential decay | nDCG@10, Catalog Coverage, Gini Diversity, Unfulfilled Hold Rate |
| **ABL-REC-01** | **w/o Temporal Recency Decay** | Set $\lambda = 0$ ($e^{-\lambda \Delta t} = 1$); treat all historic borrows with equal temporal weight | Remove time-decay discounting in user profile vector computation | Recommendation stale bias: over-recommending historical subjects read months ago |
| **ABL-REC-02** | **w/o Availability Gating** | Remove $\mathbb{I}(\text{available}(i))$; allow checked-out books to be ranked at top positions | Disable inventory copy count check in candidate filtering pipeline | Patron frustration metric: proportion of top-5 recommended titles with 0 available copies |
| **ABL-REC-03** | **w/o Semantic Similarity ($f_3=0$)** | Drop dense vector cosine similarity; rely solely on discrete categorical metadata and popularity | Set $w_3 = 0$; renormalize remaining weights $\sum w_k = 1.0$ | Serendipity, cross-subject discovery, cold-start handling for new items |
| **ABL-REC-04** | **w/o Diversity Penalty ($w_8=0$)** | Remove intra-list diversity penalty; rank strictly by raw relevance score | Omit maximal marginal relevance (MMR) or intra-list similarity penalty | Category concentration: proportion of top-5 recommendations belonging to the exact same genre |
| **ABL-REC-05** | **Uniform Weights ($w_k = 1/7$)** | Replace tuned weights with equal unweighted averaging across all active factors | Set all active feature weights to identical scalar value $1/N$ | Overall ranking quality (nDCG@10), user profile sensitivity |

## 5. Knowledge Artifact Extraction Ablations

### 5.1 Subsystem Architecture Overview
LuminaR implements a dual paradigm for educational knowledge artifact generation ([rag/services/document_knowledge.py](file:///d:/SDC/rag/services/document_knowledge.py), [rag/services/cloze_grading.py](file:///d:/SDC/rag/services/cloze_grading.py)):
1. **Deterministic Rule-Based / Graph Pipeline**: Pure CPU NLP heuristics extracting key concept definitions via syntactic regex, graph edge construction via noun-phrase co-occurrence, and Cloze deletion with phonetic and Levenshtein grading.
2. **Generative LLM Pipeline**: Prompting `Qwen2.5-3B-Instruct` with schema enforcement to generate structured flashcards, multiple-choice questions (MCQs) with distractors, and hierarchical mind maps.

## 6. Execution Protocol and Environment Controls

To guarantee that ablation differences reflect true algorithmic variance rather than hardware or environmental noise, all ablation runs must comply with the following controls:

1. **Frozen Seed and Deterministic Execution**:
   - `torch.manual_seed(42)`
   - `numpy.random.seed(42)`
   - `random.seed(42)`
   - FAISS HNSW query execution configured with fixed `efSearch` across all dense trials.
2. **Hardware Uniformity**:
   - All timing benchmarks executed on identical hardware (documented in [53_HARDWARE_REQUIREMENTS.md](file:///d:/SDC/docs/research_evidence/53_HARDWARE_REQUIREMENTS.md)).
   - GPU frequency locking or minimum 3 warm-up runs prior to measuring millisecond latencies.
3. **Identical Query and Document Splits**:
   - Exactly the same 30 evaluation queries ([labeled_evaluation_dataset.json](file:///d:/SDC/datasets/ai/evaluation/labeled_evaluation_dataset.json)) and candidate corpus must be evaluated across all search and RAG ablations.
4. **Data Recording Rule**:
   - All empirical results must be populated into the standardized result templates defined in [62_RESULT_TABLE_TEMPLATES.md](file:///d:/SDC/docs/research_evidence/62_RESULT_TABLE_TEMPLATES.md). No synthetic numbers or unmeasured placeholders may be introduced.
